단계: INCEPTION — User Stories
방법론: 하이브리드(기능 에픽 + 관통 여정 스토리) · 에픽+하위 스토리(2계층) · 수용 기준 Given/When/Then · INVEST 준수
참조: `requirements.md`(FR-*/AC-*), `personas.md`(P1 개발자, P2 디자이너, P3 AI 협업 개발자)

**범례**: 각 스토리에 `추적성`(FR/AC), `페르소나`를 표기. 수용 기준은 `Scenario` 단위 Given/When/Then.

# EPIC-1 작업 묶음 관리 (FR-1)

## US-1.1 작업 묶음 생성·이름변경·삭제
- **As** 멀티프로젝트 사용자 **I want** 작업 묶음을 만들고 이름을 바꾸고 삭제 **so that** 프로젝트별로 컨텍스트를 조직할 수 있다.
- **추적성**: FR-1.1, FR-1.2 · **페르소나**: P1, P2, P3
- **AC**
  - Scenario 생성: **Given** 대시보드에서 **When** 새 작업 묶음을 만들면 **Then** 이름을 지정한 빈 묶음 카드가 나타난다.
  - Scenario 이름변경: ⏸ **연기 (v1.1)** — **Given** 기존 묶음에서 **When** 이름을 편집·저장하면 **Then** 카드에 새 이름이 반영된다. *(FR-1.1 연기 — `#D-32`)*
  - Scenario 리소스 다수: **Given** 한 묶음에서 **When** 여러 리소스를 추가하면 **Then** 모두 해당 묶음에 표시된다.
  - Scenario 리소스 제거: ⏸ **연기 (v1.1, P1 백로그)** — **Given** 잘못 등록한 리소스를 **When** 묶음에서 제거하면 **Then** 목록에서 사라지고 영속된다. *(FR-1.2 제거측 — `#D-33`)*

## US-1.2 삭제 전 확인
- **As** 사용자 **I want** 묶음 삭제 전에 확인을 받고 **so that** 실수로 잃지 않는다.
- **추적성**: FR-1.3 · **페르소나**: P1, P2, P3
- **AC**
  - Scenario 확인: **Given** 묶음 삭제를 시도하면 **When** 확인 대화가 뜨고 **Then** 확인해야만 삭제된다.
  - Scenario 취소: **Given** 확인 대화에서 **When** 취소하면 **Then** 묶음이 그대로 유지된다.

## US-1.3 재실행 후 영속
- **As** 사용자 **I want** 앱을 껐다 켜도 묶음/리소스가 남아 있길 **so that** 작업을 이어갈 수 있다.
- **추적성**: FR-1.4, FR-11.1, FR-11.6 · **AC 매핑**: AC-1, AC-12 · **페르소나**: P1, P2, P3
- **AC**
  - Scenario 유지: **Given** 묶음과 항목을 만든 뒤 **When** 앱을 재실행하면 **Then** 동일한 내용이 그대로 보인다. (AC-1)
  - Scenario 삭제 유지: **Given** 묶음을 삭제한 뒤 **When** 재실행하면 **Then** 삭제된 항목이 다시 나타나지 않는다. (AC-12)

# EPIC-2 실행 중인 항목 표시 (FR-2)

## US-2.1 실행 중 앱·탭 패널 표시(그룹핑)
- **As** 사용자 **I want** 실행 중인 창·브라우저 탭을 왼쪽 패널에서 앱별로 묶여 보이길 **so that** 무엇이 열려 있는지 파악한다.
- **추적성**: FR-2.1, FR-2.2, FR-2.3 · **페르소나**: P1, P2, P3
- **AC**
  - Scenario 그룹핑: **Given** 같은 앱의 창이 여러 개면 **When** 패널을 보면 **Then** 앱 아이콘은 한 번만, 창 제목들이 그 아래 나열된다.
  - Scenario 실제 아이콘: **Given** 실행 중 앱 목록에서 **When** 표시되면 **Then** 각 앱은 OS의 실제 아이콘으로 보인다.

## US-2.2 선택 창 표시(녹색 점)
- **추적성**: FR-2.4 · **페르소나**: P1, P2
- **AC**
  - Scenario: **Given** 한 앱에 창이 여러 개면 **When** 그중 현재 선택된 창이 있으면 **Then** 그 그룹 안에서만 녹색 점으로 구분된다.
  - Scenario 단일창: **Given** 창이 하나뿐인 앱은 **Then** 녹색 점을 표시하지 않는다.

## US-2.3 검색 필터
- **추적성**: FR-2.5 · **페르소나**: P1, P2, P3
- **AC**: **Given** 실행 중 목록에서 **When** 검색어를 입력하면 **Then** 일치하는 항목만 남는다.

## US-2.4 더블클릭으로 최전면
- **추적성**: FR-2.6 · **AC 매핑**: AC-2 · **페르소나**: P1, P2, P3
- **AC**: **Given** 실행 중 항목을 **When** 더블클릭하면 **Then** 정확히 그 창/탭이 최전면으로 온다. (AC-2)

## US-2.5 목록 정확성(노이즈 제거)
- **추적성**: FR-2.7, FR-9.6 · **AC 매핑**: AC-7 · **페르소나**: P1, P2
- **AC**
  - Scenario 닫힌/보조창: **Given** 목록에서 **When** 창이 닫히거나 시스템 보조 창이면 **Then** 목록에서 제외된다.
  - Scenario 탭 수 일치: **Given** 브라우저에 N개 탭이 있으면 **When** 목록을 보면 **Then** 탭 수가 N과 일치한다. (AC-7)

  - Scenario 중복: **Given** 같은 창을 **When** 다시 드래그하면 **Then** 중복 등록되지 않고 한 번만 존재한다. (AC-3)

## US-3.3 파일·폴더·앱·URL 직접 드롭
- **추적성**: FR-3.3, NFR-S2 · **페르소나**: P1, P2, P3
- **AC**

  - Scenario 안전 처리: **Given** 경로/URL을 등록할 때 **When** 저장하면 **Then** 문자열 명령 조합 없이 인자로 전달·보관된다.

## US-3.4 유사 항목의 개별 등록
- **추적성**: FR-3.5 · **AC 매핑**: AC-4, AC-5, AC-8 · **페르소나**: P1, P2
- **AC**
  - Scenario 같은 앱 다른 창: **Given** 같은 앱의 서로 다른 창을 **When** 등록하면 **Then** 각각 별도 항목이 된다. (AC-4)
  - Scenario 다른 경로 폴더: **Given** 경로가 다른 두 폴더 창을 **When** 등록하면 **Then** 서로 구분되어 저장된다. (AC-5)
  - Scenario 같은 주소 다른 탭: **Given** 같은 URL을 연 서로 다른 탭을 **When** 등록하면 **Then** 별도 항목으로 추적된다. (AC-8)

  - Scenario 재확인: **Given** 사용자가 권한을 부여한 뒤 **When** 앱에서 상태를 확인하면 **Then** 실제 권한 상태와 안내가 일치한다. (AC-13)

- **AC**

  - Scenario 편집기: **Given** 서로 다른 작업 폴더의 편집기 창을 **When** 복원하면 **Then** 각각 새 창으로 해당 폴더가 열린다. (AC-6)

## US-10.3 (Windows) 최상위 창 탐색·상태 보존·복원

  - Scenario 복원: **Given** 파일 탐색기/편집기/지원 터미널을 **When** 복원하면 **Then** 등록 폴더/작업 폴더를 다시 연다.

# EPIC-12 코딩 에이전트 세션 (FR-12)

## US-12.1 코딩 세션을 리소스로 등록(Claude Code 우선)
- **As** AI 협업 개발자 **I want** 코딩 에이전트 세션을 작업 묶음에 등록 **so that** 프로젝트 컨텍스트와 함께 저장·복원한다.
- **추적성**: FR-12.1, FR-11.8 · **페르소나**: P3
- **AC**
  - Scenario 등록: **Given** 실행 중/기존 Claude Code 세션을 **When** 묶음에 등록하면 **Then** "코딩 세션" 유형 리소스로 추가된다.
  - Scenario 확장성: **Given** 도구별 어댑터 구조에서 **When** Codex/OpenCode 어댑터가 추가되면 **Then** 기존 코드 변경 없이 새 도구 세션을 등록할 수 있는 구조다.
  - Scenario 저장 범위: **Given** 세션 리소스를 저장하면 **Then** 도구 식별자와 세션 파일 위치/ID만 보관하고 대화 내용 자체는 저장하지 않는다.

## US-12.2 대화·마지막 질문·답변 완료여부 표시
- **As** AI 협업 개발자 **I want** 세션의 전체 대화·마지막 질문·완료여부를 앱에서 보길 **so that** 내 답변을 기다리는 세션을 즉시 안다.
- **추적성**: FR-12.3, FR-12.4, FR-12.5 · **AC 매핑**: AC-16, AC-17 · **페르소나**: P3
- **AC**
  - Scenario 상태 일치: **Given** 등록한 Claude Code 세션에서 **When** 카드를 보면 **Then** 마지막 질문과 답변 완료여부(사용자 입력 대기 중/대기 없음/알 수 없음)가 실제 상태와 일치한다. (AC-16)
  - Scenario 전체 대화: **Given** 세션 리소스를 **When** 열면 **Then** 전체 대화를 스크롤로 열람할 수 있다. (AC-17)
  - Scenario 자동 갱신: **Given** 세션이 진행되면 **When** 세션 파일이 변경되면 **Then** 표시가 자동 갱신된다(폴링 상한·중복 방지 준수).

## US-12.3 읽기 전용·견고한 파싱·로컬 전용
- **추적성**: FR-12.2, FR-12.6, FR-12.7, FR-12.9, NFR-S1, SECURITY-13, PBT-03 · **AC 매핑**: AC-18, AC-19 · **페르소나**: P3
- **AC**
  - Scenario 읽기 전용: **Given** 세션 대화를 표시할 때 **Then** 앱은 세션 파일을 수정·삭제하지 않는다. (AC-19)
  - Scenario 견고성: **Given** 세션 파일이 손상되거나 일부만 있어도 **When** 파싱하면 **Then** 앱이 종료되지 않고 가능한 범위를 표시한다(임의 추측 없음). (AC-18, PBT-03)
  - Scenario 로컬 전용: **Given** 세션 정보를 수집할 때 **Then** 로컬 파일만 사용하고 외부 서버로 전송하지 않으며, 대화 내용을 로그로 출력하지 않는다.

## US-12.4 세션 상태를 다른 리소스와 동일하게 표시·활성화
- **추적성**: FR-12.7, FR-12.8, FR-7.1 · **페르소나**: P3
- **AC**
  - Scenario 상태: **Given** 세션 파일이 없거나 접근 불가면 **Then** 비활성/권한 필요로 표시된다.
  - Scenario 활성화: **Given** 세션 리소스를 **When** 활성화하면 **Then** 식별 가능한 경우 연결된 터미널/에디터 창을 최전면으로 가져오고, 불가하면 세션 상세 보기로 대체한다.

# EPIC-13 앱 기동 (FR-13) — **[신설 2026-09-08]**

## US-13.1 기동 중 조작 차단과 준비 완료 신호
- **As** 앱을 방금 실행한 사용자 **I want** 앱이 준비되기 전에는 조작할 수 없고 준비 중임을 분명히 알고 싶다 **so that** 빈 목록을 실제 상태로 오해하거나 아무 반응 없는 UI를 클릭하지 않는다.
- **추적성**: FR-13.1~13.7 · **AC 매핑**: AC-21 · **페르소나**: P1, P2, P3
- **AC**
  - Scenario 입력 차단: **Given** 앱을 실행하면 **When** 스플래시가 떠 있는 동안 아래 UI를 클릭해도 **Then** 어떤 동작도 일어나지 않는다. (FR-13.1)
  - Scenario 준비 완료: **Given** 저장 묶음·Claude 상태·첫 실행앱 스캔이 모두 끝나면 **Then** 스플래시가 걷히고 화면이 이미 채워진 상태로 나타난다. (FR-13.2)
  - Scenario 깜빡임 방지: **Given** 기동이 매우 빠른 경우에도 **Then** 스플래시가 최소 표시 시간(650ms) 동안 유지되어 번쩍임으로 보이지 않는다. (FR-13.3)
  - Scenario 페일세이프: **Given** 백엔드 호출 하나가 응답하지 않아도 **When** 8초가 지나면 **Then** 스플래시가 반드시 걷혀 앱을 조작할 수 있다. (FR-13.4 · NFR-R1)
  - Scenario 정리: **Given** 스플래시가 걷힌 뒤 **Then** 오버레이는 언마운트되어 이후 상호작용을 가로채지 않는다. (FR-13.5)
  - Scenario 접근성: **Given** 보조기술을 사용하면 **Then** 로딩 구간이 진행 상태(`role="progressbar"`, `aria-busy`)로 인지된다. (FR-13.6)
  - Scenario 콜드 스타트: **Given** 번들·CSS 로드 이전 구간에도 **Then** 흰 화면이 아니라 앱 배경색이 칠해져 있다. (FR-13.7)
- **알려진 제약**: 고DPI Windows에서 WebView2가 초기 프레임을 확대 래스터화해 스플래시 카드가 잠시 커 보인다 — `known-deviations.md#H2`(결함 등록, 수정 보류). 로드된 앱 화면은 항상 정상 렌더된다.

# 관통 여정 스토리 (Journey-Spanning — 하이브리드 보강)

## JS-1 (첫 실행) 온보딩과 권한 설정
- **As** 신규 사용자 **I want** 처음 실행 시 권한/사용법을 안내받고 **so that** 바로 사용할 수 있다.
- **관통**: EPIC-10(권한) → EPIC-1(첫 묶음) → EPIC-2(실행 목록) · **추적성**: FR-10.2, FR-1.1, NFR-U1 · **AC 매핑**: AC-13 · **페르소나**: P1, P2, P3
- **AC**: **Given** 앱을 처음 열면 **When** (macOS)권한 안내를 따르고 첫 묶음을 만들면 **Then** 실행 중 항목이 보이고 등록을 시작할 수 있다.
- ⏸ **부분 미충족 (v1.1)**: macOS 권한 안내·재확인(FR-10.2/AC-13)은 `PermissionChecker` 부재로 미구현이며 백로그 유지(`#D-42`). 사용자 문서(NFR-U1)도 미제공(`#D-36`). 첫 기동 경험은 현재 US-13.1(스플래시)이 담당한다.

## JS-2 (아침 시작) 어제의 컨텍스트 복원
- **As** 멀티프로젝트 사용자 **I want** 저장한 묶음을 한 번에 활성화 **so that** 편집기·터미널·탭·폴더·세션이 복원된다.
- **관통**: EPIC-5 → EPIC-4 → EPIC-9 → EPIC-12 · **추적성**: FR-5.1, FR-4.3, FR-9.3, FR-12.2 · **AC 매핑**: AC-9, AC-11, AC-17 · **페르소나**: P1, P3
- **AC**: **Given** 저장된 묶음을 **When** 전체 활성화하면 **Then** 열린 항목은 앞으로 오고 닫힌 항목은 저장 위치/주소로 복원되며, 코딩 세션은 최신 대화/상태로 표시된다.

## JS-3 (프로젝트 전환) 대기 중 세션 확인 후 전환
- **As** AI 협업 개발자 **I want** 어떤 세션이 내 답변을 기다리는지 보고 그 컨텍스트로 전환 **so that** 병렬 작업을 놓치지 않는다.
- **관통**: EPIC-12 → EPIC-4 → EPIC-2 · **추적성**: FR-12.4, FR-12.8, FR-4.1 · **AC 매핑**: AC-16, AC-2 · **페르소나**: P3
- **AC**: **Given** 여러 코딩 세션 중 **When** "사용자 입력 대기 중"인 세션을 확인해 활성화하면 **Then** 연결된 창이 최전면으로 오고 마지막 질문을 바로 볼 수 있다.
