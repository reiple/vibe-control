# NFR 요구사항 — U7 frontend (as-built)

단계: CONSTRUCTION — U7, NFR Requirements · 소급 생성
> ⚠ **소급 생성 (2026-09-08, Q5=B)** — as-built 기술. 원 설계 의도와의 차이는 `../../../known-deviations.md` 참조.

## 성능/반응성
- 1초 폴링이 입력·드래그를 방해하지 않아야 한다(NFR-Pf1, AC-10).
  - 드래그 중 폴링 유예(`draggedApp` 가드) — 리스트 교체가 HTML5 드래그를 취소시키기 때문.
  - silent 폴링은 스피너·에러 배너를 띄우지 않음(깜빡임 억제).
  - 아이콘은 모듈 레벨 캐시 + `useState` 초기값 시딩으로 재요청·플래시 없음(NFR-Pf4).
- ✅ **NFR-Pf3 / FR-7.5 / FR-7.6 구현 완료 (2026-09-08)** — 폴링 절약:
  - `document.hidden`이면 틱을 건너뛴다(창이 숨겨지거나 최소화된 동안 OS 창 열거를 하지 않음)
  - `visibilitychange`로 복귀하면 **즉시 1회 갱신** — 남은 틱을 기다리며 낡은 목록을 보여주지 않는다
  - `window.resize` 이후 **400ms 유예** — 창 크기 조절이 1초 OS 열거와 경합하지 않게 한다
  - `pollInFlight` 가드 — 이전 폴링이 아직 응답 전이면 다음 틱을 건너뛴다(FR-7.6 동시성 가드). 명시적 ↻는 사용자 의도이므로 가드하지 않는다
  - **한계**: 좌측 패널의 CSS `resize` 핸들 드래그는 `window.resize`를 발생시키지 않아 유예 대상이 아니다(요구사항 문구인 "창 크기 조절"은 창 자체를 가리킨다)
- **부팅 체감(FR-13)**: 최소 650ms / 하드캡 8000ms / 페이드 400ms.

## 신뢰성
- `Promise.allSettled`로 부팅 — 한 호출 실패가 스플래시를 걸리게 하지 않는다.
- `finish()` 멱등 + 하드캡 → **UI가 스플래시 뒤에 영구히 갇히지 않는다**(FR-13.4).
- 모든 비동기 이펙트에 `cancelled` 플래그 — 언마운트 후 늦은 resolve 무시.
- 세션 스냅샷 일시 실패 시 마지막 정상 값 유지.
- `errText()`로 Tauri 오류 객체에서 사람이 읽을 메시지 추출(`[object Object]` 방지).

## 사용성/접근성
- 다크 대시보드(FR-8.1), 넓은 화면 2열 / 좁은 화면 1열(FR-8.4), 고해상도 아이콘(FR-8.7 / §13.5).
- 스플래시에 `role="progressbar"` + `aria-label` + `aria-busy`(FR-13.6). 장식 요소는 `aria-hidden`.
- 파괴적 동작(묶음 삭제)은 인라인 확인 단계를 거친다(FR-1.3).
